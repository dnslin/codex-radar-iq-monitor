# 验证真实工具栏弹窗

普通浏览器标签页不能验证扩展弹窗的自然尺寸。v0.6.0 的 `max-width: 100vw` 曾让 Chrome 将工具栏弹窗压到约 182px；在标签页手动设置 720px 视口会掩盖这个问题。

准备 Node.js 22 或更新版本，以及可在命令行运行的 `agent-browser` 和它使用的 Chrome。检查需要桌面窗口和可访问的雷达Bench公开目录与成绩摘要，不需要安装项目运行依赖。

在仓库根目录运行：

```bash
node scripts/verify-popup.mjs
```

发布前应解压实际 ZIP，再把解压目录传给同一个检查脚本。可选的第二个参数保存真实弹窗截图：

```bash
unzip dist/codex-radar-iq-monitor-v0.9.0.zip -d /tmp/radar-release-check
node scripts/verify-popup.mjs /tmp/radar-release-check /tmp/radar-popup.png
```

脚本使用独立浏览器会话加载指定目录，通过 `chrome.action.openPopup()` 打开真实工具栏弹窗，检查结束后关闭会话。它不设置弹窗视口，而是检查 Chrome 自然生成的尺寸为 720 × 600px，列表高度至少为 250px，页面和列表无横向溢出。

交互与数据检查应覆盖：

- 全部厂商展示后台新版快照中的全部模型，记录不重复归组。模型与档位来自公开目录，不把 6 个模型、34 个档位写成永久固定数量。
- 当前目录的 OpenAI / Codex 记录正确归组。接口未提供 DeepSeek、Claude 等记录时不以旧数据补齐，也不要求这些厂商必须存在。
- 厂商和运行工具筛选、模型名称搜索、名称排序及清空空结果可用。手动刷新后保留当前筛选。
- 主行显示已测档位中的最高分及对应思考等级，覆盖与样本来自该档位。展开后各档位成绩与服务端摘要一致，不生成跨档“总体 IQ”。
- 深浅主题切换，以及模型行展开后详情可见。
- 固定测试快照中，未覆盖全部题目的档位显示“阶段分”，全部覆盖时不显示阶段分提示。单元测试另覆盖 63/64 与 64/64 的边界，不能沿用旧版达到 60% 即不提醒的政策。
- 合法 0 分保留为 0 分。`score: null` 的档位显示待采样，不显示为零分。计分样本量使用 `graded_runs_count`，不使用全部历史统计样本量替代。
- 页面及无障碍说明使用“雷达Bench”与“雷达分”。本地读取时间、目录时间和历史日期不混用。
- 厂商导航和组标题使用对应的本地 SVG，图像已加载，图标带 `aria-hidden="true"` 且图片 `alt` 为空，避免屏幕阅读器重复读品牌名称；全部及其他分类使用通用图标。
- 深浅主题下，厂商导航全部可见，正文、导航和次级文字的计算颜色与实际叠加背景达到至少 4.5:1 对比度。输出报告最低对比度。
- 通过真实 Tab 按键检查导航焦点，焦点轮廓至少为 2px，与背景对比度至少为 3:1；同时覆盖未选中、选中及悬停状态。内缩轮廓使用按钮自身背景计算对比度。

颜色检查覆盖列出的界面文字及实体背景颜色。品牌图形本身不作为文字检查，完整视觉效果仍需查看保存的真实截图。

阶段分和缺失值检查可在独立浏览器会话中临时保存固定测试快照，完成后恢复实时快照。它不修改日常使用的浏览器数据。固定快照用于覆盖边界状态，不能替代实时目录与成绩读取验收。

接口不可用或实时配置未在等待时间内加载完成，应让检查失败并保留错误信息。尺寸回归时仍应保存截图；尺寸正常时，截图等待实时数据加载后再保存。发布验收还需核对 ZIP 内版本号及权限：0.9.0 使用 `https://codexradar.com/*`，不保留旧 API 域名权限。
